# SafeDrive 研究账本使用说明

全部数据都是虚构代驾服务的合成记录。页面中的结果由独立 Python oracle 推导，不是 MySQL 查询实测，更不是经营或司机质量结论。

## 从一个边界开始

在普通浏览器打开 `web/reader.html`。不需要安装、账号、网络或数据库。当前执行环境无法打开该文件做浏览器验证，所以以下是实现的操作路径，不能当作已完成的浏览器验收。

1. 默认问题 Q10 检查逾期未结算。看完成时间、支付状态和证据订单编号，点击行号，检查关联订单。
2. 切换到“边界案例”，对照17号恰好24小时与18号多一秒；七天边界是19/20号。点案例查看原始事件；返回关联问题检验定义。
3. 把报告情景改为“时点后移1小时”。17号进入逾期集合，19号移出七天窗口。改变的是报告定义，不是策略产生的效果。
4. 在 Q02 对照服务队列净结算与窗口净现金；29号旧服务可以在新窗口收款。Q07 必须结合评价覆盖阅读均值。
5. 选中结果行，再点订单编号，核对请求、预约、完成、支付、退款和评价时点；未来事件标为时点未到。展开原始关系记录检查重派、事件和保管记录。
6. 展开 SQL。导出的 SQL 会先明确设置所有参数，避免沿用另一个会话的变量；页面不执行 SQL。导出的CSV文件名明确写着 `python-expected`。

Q09 用车辆证据；零车辆型号显示0而不是NULL。其他问题的证据单位是订单或评价，不能混用分母。原课程 TSV 在“保留原课程结果”里完整保留；新旧夹具与口径不同，不能用它们计算业务增长率。

## 写下判断，再回来检查

“记录一个证据支持的判断”绑定当前问题、报告情景和选中行。先引用证据，再写结论和限制。保存只检查引用与最低文字长度，不评分、不声称正确性或学习进步。

最近20条笔记保留在本浏览器。更改时点或问题后，历史判断标记为旧口径，需要重新检查；草稿按问题/情景分别保存。正式留存请导出 JSON。存储失败时保留当前草稿并提示复制。浏览器存储和下载恢复尚未实测。

## 结果与验证的区别

- 33个订单、18个边界案例、7种报告预设 / 70张结果表全部是合成 Python 预期值。
- 18项 Python测试、CHECK字段引用检查、JS语法和文件审计已通过。
- Payment表的错误保管字段约束已从候选中移除；33号未评价服务的说明已校准到夹具事实。
- 真 MySQL 建表、查询、触发器、约束与事务回滚仍未运行。本公开版本未提供 MySQL 实跑验证，不自动启动或重建数据库。
- HTTP/浏览器/手机/键盘/下载/存储交互需另行验收；当前发布验收状态见 README。源码完成与静态通过不表示这些已通过。

完整来源和当前源码 SHA-256 在 `evidence/verification.json`；SQL运行的安全入口及未来复验命令见 README。低于5GiB停止生成新文件，使用已有依赖，单任务数学线程最多2。没有读取凭据、删除用户文件、收费API或公开发布。

本次约束扩展另有32个纯数据接受/拒绝案例；定义、合法变更路径与未实测的SQL探针见 `CONSTRAINTS.md`。原33订单夹具和18分析边界不变。
